Worth knowing before you review

Goods shows 0 products, and that is on purpose

Odoo's stat button on Goods reads 11; ours reads 0. Goods holds no product of its own — all eleven sit in its four children — and Odoo's help for that field says, in its own words, that it “Does not consider the children categories”. Its code does the opposite and counts the whole subtree. A HAP roll-up aggregates one relation, not a subtree, so we built what the help promises and put the children right beside it: open Goods and its Child Categories tab lists 2 · 2 · 4 · 3, which is the 11. If you would rather match the number Odoo actually shows, say so and it becomes a small workflow.

The recursion is real

Complete Name is a function formula reading a stored lookup of the parent's own Complete Name — a chain that refers to the same worksheet, which the requirements warned HAP might refuse. It does not refuse, so no fallback was needed and the expression is the one §1 asked for:

IF(ISBLANK(Parent Complete Name), TRIM(Name), CONCAT(Parent Complete Name, " / ", TRIM(Name)))

It was proved four levels deep, two deeper than the tenant goes, and a rename at the top carries all the way down in one save with no workflow behind it. # Products is HAP's own 汇总 control, the first in this app, counting the Products list beside it; it follows a product moving in or out within seconds.

CLI self-checks: every control, permission, the formula, the lookup, the roll-up, the view and Products' Category read back as specified; the seven categories and all fourteen products' categories match the extract exactly; the other six worksheets were compared control by control before and after every save and are unchanged, as are products.py verify and variants.py verify.

Differences from Odoo

  1. 1
    # Products counts this category onlyYour call

    Goods reads 0 here and 11 on the tenant. Deliberate, and it is what Odoo's own help text promises while its code counts the subtree. The Child Categories tab shows the missing 11 one glance away. A workflow could match Odoo's number if you prefer it.

  2. 2
    A cycle is acceptedYour call

    Odoo raises “You cannot create recursive categories.”; HAP has no rule that can ask whether a record is its own ancestor. What happens instead is cosmetic and reversible — the Complete Name repeats the path, and a two-record cycle lengthens it a level on each save. Nothing hangs and one edit puts it right. A workflow could refuse a parent whose Complete Name already contains this category's, which would catch every cycle the chain can see.

  3. 3
    Name is required in the form onlyHAP behaviour

    Odoo's is a NOT NULL column. HAP's is a form check, so the API wrote a nameless category without complaint — the same class of thing as a text field's maximum length. Seed and import scripts have to check it themselves.

  4. 4
    The two lists are tabs, not fieldsHAP behaviour

    HAP renders a list-style relation as a tab at the foot of the record, so Child Categories and Products sit under # Products rather than in the form grid. Odoo puts neither on a view at all.

  5. 5
    The stat button is a list, not a jumpNote

    Odoo's button carries a number and opens a filtered product list; here the products themselves are on the record, with the number above them.

  6. 6
    The tenant cannot sort its own category listOdoo 19.4

    19.4 stopped storing complete_name, so ordering on it is refused outright and the tenant returns roots first, then each parent's children by name. HAP stores its formula, so our view is sorted the way Odoo's source asks and reads as the tree.

  7. 7
    A record just created sits at the topHAP behaviour

    Whatever the sort, until the view is reloaded — worth knowing before reporting a sort as broken.

  8. 8
    Deleting a parent does not take its childrenNote

    Odoo's parent_id is ondelete='cascade'. HAP does not cascade, so the children would survive pointing at nothing. Not tested — nothing is deleted here without your approval.
