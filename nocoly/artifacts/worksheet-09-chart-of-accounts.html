Worth knowing before you review

None of the new account fields is required — on purpose

Odoo marks a contact's receivable and payable accounts, and an invoice line's account, as required. But Odoo also hides those fields from part of the accounting staff — an Invoicing user never sees them — and in HAP a field that is required yet hidden from a role blocks every save that role makes. So the defaults, the seed and an automation keep them filled instead, and the tests check that they do. Journals is the exception: only the two roles that see its accounts can edit a journal, so a rule requires them there. One thing to try yourself: switch an account's Type to Receivable. The message "You cannot have a receivable/payable account that is not reconcilable." appears at once and you tick the box; Odoo ticks it for you.

Differences from Odoo

  1. 1
    A receivable or payable account's box is ticked by handHAP behaviour

    HAP checks a rule before the save and runs a workflow after it, so the automation that sets Payment Reconciliation cannot beat the rule that requires it.

  2. 2
    The new account fields are not requiredDecision

    Required and hidden from a role would block that role's saves. Defaults, the seed and automation B keep them filled; Journals, edited only by roles that see its accounts, requires them.

  3. 3
    Checks that live in the form onlyHAP behaviour

    The code format, the receivable rule and every default hold in the form; the API writes around them. No duplicates holds everywhere.

  4. 4
    A product and an account set in the same saveHAP behaviour

    Automation B gives the line the product's account and overwrites the one chosen; Odoo keeps an account written with the product.

  5. 5
    One level of categoryNote

    Odoo walks up a category's parents for an account; every category here carries one, so automation B reads the product's own category.

  6. 6
    No debit, no credit, no balanceScope

    No Balance button, no Account with Entries filter, no tax or payment-term lines — double entry is beyond this bundle.

  7. 7
    Pickers that cannot follow the recordHAP behaviour

    A journal's Default Account picker offers every account, where Odoo narrows it by the journal's type; a Parent Account picker cannot leave out the account's descendants.

  8. 8
    Odoo creates a bank journal's account when left emptyHAP behaviour

    Here the rule requires one instead.
