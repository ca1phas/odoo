Not a backlog. The first twelve have no counterpart in Nocoly at all; the last one is only waiting on a payment provider.

Impossible in Nocoly
ActivitiesNo scheduling model, so Odoo's Activity button, Activities column and activity views have nothing to map to.
FollowersComments reach Nocoly users only — there is no per-record subscriber list and no external contacts.
Customer portalShare gives a view-only public page. Odoo's accept, sign and pay online flow can't be reproduced.
Side-by-side column groupsNocoly has one 12-column grid, so Other Info reads top to bottom in Odoo's order instead of in two columns.
Journal fieldNo counterpart on the Nocoly order.
Insert in spreadsheet · Upload Request for QuotationTwo entries in Odoo's list cog with no Nocoly equivalent.
Relation defaults never fireThe platform limit behind item 14 — autofill from a product or customer can only ever be a workflow that runs after save.
Buttons under the order linesNocoly can't put controls inside the lines table, focus the new row's description, or refresh the table live — so Add Section, Add Note and Add Subsection live under More (item 11).
Per-user Group By inside the listNocoly only groups a list for everyone, by one field, never by date. Odoo's ad hoc, multi-level Group By would need a custom view plugin replacing the lists (item 13).
Column defaults for everyoneHiding a column by default and locking always-visible columns only work per user in Nocoly (item 12).
Rules on automated writesNocoly's form rules — like "sections need a description" — don't apply to API or workflow writes; Odoo enforces them in the database.
Subtable workflows and stored lookupsWorksheet-event workflows never fire on subtable-mounted sheets, and new stored lookups stay blank until a manual Calibrate Data run, capped at once per sheet per two hours.
Needs an integration, not impossible
Payment Link · Capture / Void · Payments smart buttonAll three need Stripe. Nothing to build until the account exists.
