Contacts show “Company, Person”, like Odoo

Odoo names a company’s contact “Company, Person” and a nameless address “Company, Delivery” — in lists, cards, record titles and partner pickers. At the owner’s request, Display Name, a formula, is now the title field. Rerunning the six tests it touches showed the Contacts and Archived tables had lost their Display Name column (HAP never shows a hidden field as a column), so Display Name now shows read-only on a saved contact’s form, under Image. Check it on any record and in the Contacts and Kanban views.

History

Built first from the Odoo 19.0 source, then moved to 19.4 the same day, keeping every id: the Person / Company switch removed, DUNS added, the rules and views that depended on the switch retired, Company shown on every contact. A last pass copied Company ID and DUNS on linking, kept archived companies out of the Company picker, and stopped the push automation running for contacts that have nobody under them.

After the first UI test the owner asked for Odoo’s display name. Parent name and Display Name were added and Display Name made the title field; the views moved to Display Name columns and sort. Renaming the test company updated its contacts’ Display Name within six seconds. Rerunning the tests it touches showed that HAP never shows a hidden field as a table column, so Display Name became read-only and hidden on create instead of hidden.

Cleanup

  • The 3 rules the 19.0 build left disabled — Company is hidden on companies, Job Position only for persons, Company ID only on stand-alone companies — were deleted in the form designer with the owner’s approval.
  • The workflows of a duplicate Archive / Unarchive pair were already gone: HAP deletes a button’s workflow with the button.

Differences from Odoo seen in testing

  1. 1
    Display Name on the formNote

    Names now match Odoo in lists, cards, titles and pickers. Unlike Odoo, a saved contact’s form also shows Display Name, read-only, under Image — HAP never shows a hidden field as a table column.

  2. 2
    Archive and UnarchiveNote

    The button that does not apply is greyed out rather than hidden.

  3. 3
    “Modifying form data” barHAP behaviour

    After adding a contact from the Contacts tab, or picking a Salesperson, an open record keeps a Modifying form data — Cancel / Save bar although the change is already stored. Clicking Save clears it.

  4. 4
    Kanban cardNote

    The image sits on top of the card; Odoo puts the avatar on the left.
